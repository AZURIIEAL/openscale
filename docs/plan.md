The OpenScale project is built around the New York City Taxi & Limousine Commission (TLC) Trip Record Dataset, one of the most widely used public datasets in data engineering, distributed systems, and big-data research. The dataset contains real taxi trip records collected from New York City taxis, with each record representing a completed journey and containing information such as pickup and drop-off timestamps, locations, trip distance, passenger count, fare amount, payment type, tips, and total charges. The data is published monthly in Apache Parquet format and spans many years, resulting in hundreds of millions to billions of records when multiple years are combined. It is frequently used in industry demonstrations, research papers, Spark-based analytics projects, and large-scale data processing experiments because it provides realistic, messy, and high-volume data that closely resembles what engineers encounter in production environments.

The reason for choosing this dataset is not to build another taxi analytics dashboard or machine learning model. Instead, the dataset serves as the raw fuel for constructing a complete modern data platform. Small datasets such as Titanic, Iris, or house-price datasets are useful for learning machine learning concepts but do not adequately demonstrate skills in data engineering, distributed processing, streaming architectures, observability, data governance, or large-scale analytics. The NYC Taxi dataset allows the project to showcase real-world engineering challenges such as handling large volumes of data, dealing with schema evolution, managing data quality issues, implementing distributed ETL pipelines, building streaming systems, creating analytical workloads, and supporting machine learning use cases. The objective is to demonstrate the ability to design and implement systems similar to those used by companies such as Uber, Airbnb, Databricks, Snowflake, or Lyft rather than simply training predictive models.

The final vision of OpenScale is to become a miniature urban mobility data platform that combines batch processing, streaming analytics, machine learning, observability, and modern lakehouse principles into a single end-to-end architecture. The platform will begin by ingesting raw NYC Taxi datasets and storing them in a data lake using MinIO. The data will then flow through a Medallion Architecture consisting of Bronze, Silver, and Gold layers. The Bronze layer will preserve raw source data, the Silver layer will perform cleansing and standardization, and the Gold layer will generate business-ready analytical datasets such as daily revenue, hourly demand, congestion metrics, and zone-level statistics. A custom data-quality framework will validate datasets during each processing stage by checking for null values, duplicates, schema violations, and invalid business rules. After the batch-processing pipeline is complete, historical taxi records will be replayed into Apache Kafka to simulate a live production environment. Spark Streaming jobs will consume these events and generate real-time analytics, creating a platform that behaves similarly to a modern ride-hailing company's internal data infrastructure.

As the platform evolves, additional capabilities will be added. A feature store built using Redis and PostgreSQL will manage machine learning features for demand forecasting, fare prediction, and congestion prediction models. MLflow will track experiments, model versions, and deployments. FastAPI services will expose predictions through APIs, while ClickHouse will power high-performance analytical workloads. Observability will be implemented using Prometheus, Grafana, and OpenTelemetry to monitor system health, pipeline latency, Kafka lag, Spark throughput, data quality scores, model performance, and API metrics. Benchmarking experiments will be conducted using datasets ranging from one hundred million to one billion records to evaluate throughput, storage efficiency, execution time, memory utilization, and scalability characteristics. The final result will not be a simple analytics application but a complete data-intensive intelligent software system that aligns closely with the themes emphasized by programmes such as EDISS and DEAI.

From a learning perspective, OpenScale provides exposure to nearly every major discipline involved in modern data platforms. In Data Engineering, it teaches ETL design, ELT workflows, data lakes, lakehouse architectures, partitioning strategies, schema management, and data quality engineering. In Distributed Systems, it introduces parallel processing, fault tolerance, distributed computation, and Spark execution models. In Streaming Systems, it provides practical experience with Kafka, event-driven architectures, stream processing, and real-time analytics. From a database perspective, it demonstrates the different roles of PostgreSQL, ClickHouse, Redis, and object storage systems such as MinIO. On the machine learning side, it covers feature engineering, feature stores, MLOps, experiment tracking, model lifecycle management, and production inference systems. The project also introduces DevOps concepts through Docker and Docker Compose while building expertise in observability through metrics collection, tracing, dashboards, monitoring, and alerting. By the end of the project, the knowledge gained will extend far beyond machine learning or software development and into the broader domain of building scalable, production-grade data platforms.

Ultimately, OpenScale is designed to transform a publicly available dataset into a showcase of systems engineering capability. Rather than presenting a collection of isolated projects, it demonstrates the ability to design, implement, monitor, scale, and evolve a complete data platform. This is precisely the type of project that aligns with the interests of master's programmes focused on Data Engineering, Distributed Systems, MLOps, Artificial Intelligence, and Data-Intensive Intelligent Software Systems, making it a strong portfolio piece for applications to programmes such as EDISS and DEAI.
